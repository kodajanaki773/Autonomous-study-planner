# Aarogya Drishti API data layer

This directory is an isolated FastAPI-project persistence foundation; the current repository's existing MERN app is not modified. It defines PostgreSQL SQLAlchemy models, an Alembic initial migration, encrypted sensitive fields, and synthetic geography/patient seed data. No clinical inference or diagnosis is generated by the seed.

## Setup

From `api/` in PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Set `DATABASE_URL` to a local PostgreSQL database named `aarogya_drishti`. Generate a unique local `ENCRYPTION_KEY`:

```powershell
python -c "import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

Put the generated value in the ignored `api/.env` file. Never reuse it across environments or commit it. The sample connection string is local-only; change its password before use.

## Migrate and seed

```powershell
alembic upgrade head
python seed.py
```

The seed creates the 11 specified mandals, two explicitly labelled **sample** PHCs, gram panchayats, villages and habitations per mandal, seven role accounts, and 40 synthetic patients. The hero scenario is 46 years old, assigned to G. Madugula, and has synthetic tobacco-chewing and white-cheek-patch entries. It is not a diagnosis. All phones use the fictional NANP `202-555-01xx` range, then are encrypted at rest.

Seeded role accounts are inactive and contain random, unrecoverable password hashes. This prevents accidental shared/default credentials; provision individual credentials and MFA through a future authentication flow before enabling accounts.

## Reset (destructive)

Reset is limited in code to `development`/`test` on local PostgreSQL and the exact database name `aarogya_drishti`. It additionally requires `ALLOW_DATABASE_RESET=true` in `api/.env` and an explicit flag:

```powershell
python reset.py --confirm-reset
```

It drops the `public` schema and reseeds it. Do not run against data you need.

## Data integrity

- Every record has UUID, timestamps, `created_by`, and version fields. Foreign keys use `ON DELETE RESTRICT`.
- `diagnoses` enforces a linked reviewed report reference for `pathology_confirmed_malignancy`.
- PostgreSQL triggers reject updates/deletes to `ai_inferences` and `audit_logs`; clinical tables reject hard deletes.
- Patient and account names, phone numbers, addresses, free-text clinical notes, and similar sensitive values are represented by ciphertext fields. `app.crypto` uses AES-GCM; configure a 32-byte URL-safe base64 key.
- Geography and localized education labels remain plaintext; they are not personal identifiers.
- The initial migration creates the schema from the SQLAlchemy metadata in this scaffold. For production, freeze generated DDL in reviewed Alembic revisions before deploying schema changes.

Run schema/encryption unit tests with:

```powershell
python -m pytest
```
